# CampusHub 校园圈 · MVP V0.1

使用微信小程序原生 JavaScript / WXML / WXSS / JSON 的校园生活演示项目。无需安装 npm 依赖，无外部 UI 框架、外部图片、真实 AppID 或云服务。三所学校（星澜大学、青禾理工学院、云栖师范学院）、用户和商家均为虚构。

## 零基础导入和运行

1. 从微信官方渠道安装最新版稳定版「微信开发者工具」，打开工具并扫码登录工具本身。
2. 选择导入项目，目录选择本 README 所在的 `campushub` 根目录，**不要只选择 miniprogram 文件夹**。
3. 项目名称填写 CampusHub。AppID 选择「测试号」或「不使用 AppID」模式（不同工具版本名称可能不同）；配置中的 `touristappid` 表示游客项目，并非真实 AppID。选择普通小程序、不使用云开发。
4. 确认源码目录为 `miniprogram/`，点击导入，然后点击「编译」。不需要运行构建或安装依赖命令。
5. 在模拟器中使用底部的首页、二手市场、需求广场、校园周边、我的。若工具提示游客模式能力限制，本项目不使用这些受限的后台能力。真机预览、上传发布及某些工具版本的账号限制可能需要真实 AppID；这些不属于本地演示要求。

## 已实现

- 首页：品牌、全局学校选择、市场搜索入口、推荐商品、最新需求。
- 市场：关键词、分类和学校组合筛选，商品详情，带校验的商品发布。
- 需求：摄影约拍、足球招募、拼车、学习互助；筛选、详情和发布。
- 周边：按学校筛选的虚构示例商家，明确显示演示标识。
- 我的：虚拟用户、本机发布记录和发布入口。
- 发布后跳转详情；重新打开页面及重启模拟器后从 `wx.getStorageSync` 读取。学校选择在首页、市场、需求和周边之间共享。

## 手动测试

1. 初次打开首页，切换三所学校及「全部学校」，确认推荐和需求随之更新；切换市场、需求、周边，确认学校一致。
2. 在市场搜索「耳机」，切换数码/书籍/生活/运动分类，再清空关键词和筛选，查看结果与空状态；点击商品打开详情。
3. 发布商品：检查空标题、过短描述、0、负数、超过 99999.99、超过两位小数的价格会被拒绝；输入有效信息后查看详情和「我的商品」。选择全部学校后确认市场中可找到新商品。图片是占位，不上传。
4. 发布需求：检查标题、描述、模拟联系方式的必填和长度限制；用虚构联络代号发布，确认需求详情、广场和「我的需求」显示。
5. 重启模拟器，确认发布记录仍在；使用工具的「清缓存 → 数据缓存」后重新编译，确认回到初始 Mock 数据。不要清除需要保留的数据。
6. 点击详情里的模拟交易/联系按钮，确认只有演示提示；访问不存在的详情 ID，确认显示空状态并能返回列表。
7. 在不同尺寸模拟器检查五个底部导航、滚动、表单键盘、普通页面返回和长文本换行。

## 静态及逻辑检查

机器装有 Node.js 时，在根目录执行：

```sh
node scripts/check.js
```

该命令检查 JSON、JS 语法、配置路径、底部导航资源、WXML 事件处理函数、本地 services 的校验和存储逻辑，以及页面模拟跳转和表单提交。它不能代替微信开发者工具的 WXML/WXSS 编译或真实交互测试。无需 npm install。

## 数据和限制

商品、需求和学校选择保存在 `campushub_v01` 本地存储键下。初始示例通过 services 合并，不会覆盖本地发布。存储失败会提示用户，不会声称发布成功。没有真实支付、私信、身份认证、活动报名、地图导航、广告收费或图片上传。请不要输入真实个人信息；模拟联系方式也会明文保存在本机。代码不记录用户输入到日志。

## 结构和下一阶段

- `miniprogram/pages/`：五个 Tab 页面、商品/需求详情、商品/需求发布，共九页。
- `miniprogram/services/`：Mock 数据与同步本地数据适配器，未来云接口的替换边界。
- `miniprogram/utils/`：共享交互辅助；`assets/`：本地 Tab PNG 图标。
- `cloudfunctions/`：云函数预留；`docs/`：架构与云开发路线；`scripts/`：无依赖检查。

未来接入云开发需要真实 AppID、云环境及权限配置，并把同步 services 调用改为异步接口，增加加载/错误状态；详见 [云开发路线](docs/cloud-development.md)。
